# 콘텐츠 골든타임 예측 모델 — 코드 스켈레톤

2026 한국관광 데이터랩 활용 경진대회, 후보 11 "콘텐츠 흥행 → 실제 방문 급증까지의
골든타임 예측 모델" 구현용 프로젝트.

## 지금 상태

- **mock 데이터로 전체 파이프라인이 끝까지 돎** (`python main.py` 바로 실행 가능,
  API 키 없어도 됨)
- KOBIS(영화 박스오피스) / 네이버 데이터랩(검색어트렌드) / 네이버 뉴스 검색
  → **실제 API 연동 코드까지 이미 작성됨** (`collectors.py`). API 키만 발급받아
  `.env`에 넣고 `USE_MOCK_DATA=false`로 바꾸면 실데이터로 전환됨
- 한국관광 데이터랩(방문자수·검색건수)만 공개 API가 확인되지 않아, 수동 다운로드한
  CSV를 읽는 방식으로 남겨둠 (`collectors.get_datalab_tourism_visits`의 docstring 참고)

## 설치

```bash
cd golden_time_project
pip install -r requirements.txt
cp .env.example .env   # 실제 API 키가 있으면 .env에 채워넣기 (없어도 mock으로 실행 가능)
```

## 실행

```bash
python main.py
```

`output/` 폴더에 케이스별 시계열 그래프(`*_timeseries.png`), 워드클라우드
(`*_wordcloud.png`), 민감도 분석 결과(`*_sensitivity.csv`)가 생성되고,
콘솔에 골든타임 갭 요약표가 출력됨.

민감도 분석은 "급증 판정 기준(표준편차 배수)이나 평시 기간을 조금씩 바꿔도
골든타임 갭이 크게 안 흔들리는가"를 격자탐색으로 확인하는 것 — 사례가 1개뿐일 때
결과가 특정 임계값 선택에 좌우된 우연이 아님을 보여주는 최소한의 근거로 씀
(`analysis.sensitivity_analysis` 참고).

## 테스트

```bash
pytest
```

mock 데이터로 전체 파이프라인이 에러 없이 도는지만 확인하는 스모크 테스트.
**회의에서 config.py 정의가 바뀐 뒤에도 이 테스트가 통과해야 정상** — 실패하면
어딘가 반영 실수가 있다는 뜻.

## 파일 구조 및 역할

| 파일 | 역할 | 회의 결정 반영 위치 |
|---|---|---|
| `config.py` | 전역 설정 — 케이스 목록, 골든타임 정의, 통제변수 on/off | **여기 대부분** |
| `collectors.py` | 데이터 수집 (KOBIS/네이버데이터랩/데이터랩방문자/뉴스/리뷰) | 새 데이터 소스 추가 시 |
| `preprocess.py` | 시계열 정렬, 통제변수 플래그, 평시 대비 초과분 계산 | 통제변수 종류 추가 시 |
| `analysis.py` | 검색 급증일 탐지, 골든타임 갭 계산, 교차검증, 키워드 빈도 | 급증 판정 기준·검증 방법 |
| `visualize.py` | 시계열 그래프, 워드클라우드 | 그래프 형태 바뀔 때 |
| `main.py` | 전체 파이프라인 실행 | (거의 안 바뀜) |
| `tests/test_pipeline_smoke.py` | mock 데이터로 파이프라인 무결성 확인 | (거의 안 바뀜) |

**설계 원칙**: 회의에서 바뀔 가능성이 높은 값(골든타임 정의, 급증 임계값, 케이스
목록, 통제변수)은 전부 `config.py` 한 곳에 몰아뒀음. 다른 파일들은 그 값을
참조만 하도록 짜여있어서, 정의가 바뀌어도 대부분 `config.py`만 고치면 됨.

## 아직 회의에서 정해야 할 것 (config.py의 TODO 주석과 연결됨)

1. **골든타임 시작점/끝점 정의** (`GOLDEN_TIME_START_DEF`, `GOLDEN_TIME_END_DEF`)
2. **검색량 "급증" 판정 기준** (`SPIKE_THRESHOLD_STD_MULTIPLIER`) — 지금은
   임시로 "평시 표준편차의 2배"로 잡아둠
3. **시험기간 통제변수 정의** (`CONTROL_VARIABLES["is_exam_period"]`) — 지금은
   구현 안 돼 있고 켜도 전부 False로만 나옴
4. **대조/추가 사례 확보** — 지금 케이스가 1개(영월)뿐이라 `leave_one_case_out_check`가
   사실상 비어서 나옴. 최소 2~3개는 있어야 교차검증이 의미가 생김
5. **한국관광 데이터랩 다운로드 방식 확정** — 일 단위 다운로드가 되는지, 로그인이
   필요한지 확인 후 `get_datalab_tourism_visits`의 CSV 컬럼명만 맞춰주면 됨

## 알아둘 제약사항

- KOBIS 일별 박스오피스 API는 **그날의 상위 10위 영화만** 반환함. 흥행작은 문제
  없지만, 흥행이 약한 대조군 영화를 추가하면 특정 날짜에 결측(NaN)이 생길 수 있음
- 네이버 데이터랩 검색어트렌드는 **절대 검색량이 아니라 구간 내 최댓값을 100으로
  한 상대지수**임 — 서로 다른 지역/키워드 그룹 간 절대 비교는 불가능하고, 같은
  키워드의 시간 흐름(개봉 전후 변화)을 보는 용도로만 쓸 것
- 워드클라우드에 한글이 네모(□)로 깨지면 `visualize.plot_wordcloud(..., font_path=...)`
  에 나눔고딕 등 한글 폰트(.ttf) 경로를 넘겨줄 것
